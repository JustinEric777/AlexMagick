# Alex Magick 介绍与使用指南

## 项目介绍

Alex Magick 是一个综合性的 AI 平台，旨在将现代人工智能的各种能力统一到一个易于访问的工作区中。它是为开发人员、研究人员和爱好者设计的，让他们无需为每个模型单独配置环境，就能轻松实验和使用各种 AI 模型。

Alex Magick 的核心理念是**统一与高效**。它抽象了不同推理后端（如 PyTorch 和 OpenVINO）和模型架构的复杂性，提供了统一的交互接口。无论您是使用 Stable Diffusion 生成艺术作品、与大语言模型聊天，还是合成语音，体验都是无缝的。

### 架构亮点

-   **懒加载与单例引擎**：为了优化资源使用（特别是在消费级 GPU 上），Alex Magick 确保只有当前活跃的模型占用内存。在任务之间切换（例如从图像生成切换到聊天）会自动卸载前一个模型。
-   **适配器模式**：系统使用复杂的适配器层 (`core.models.adapters`) 来标准化调用。这意味着添加新模型通常只需要更新配置和编写简单的包装器，而无需重写核心逻辑。
-   **本地向量存储**：使用 **Milvus Lite** 进行高效、独立的向量数据管理。这使得 RAG（检索增强生成）和历史搜索功能无需外部依赖即可运行。

## 使用指南

### 1. 快速开始

安装完成后（参见 `README_zh.md`），启动应用程序：
```bash
python webui.py
```
打开浏览器并访问 `http://localhost:7860`。

### 2. 界面概览

界面主要分为代表不同 AI 领域的标签页：

-   **序列 (Sequence)**：基于文本的任务（LLM 聊天、翻译、嵌入）。
-   **图像 (Image)**：视觉生成与编辑（文生图、图生图、图像修复）。
-   **音频 (Audio)**：语音处理（语音合成 TTS、自动语音识别 ASR）。
-   **视频 (Video)**：视频分析（嵌入）。
-   **多模态 (Multimodal)**：处理多种输入类型的模型（例如 图+文 聊天）。

### 3. 任务操作指南

#### A. 与 LLM 聊天 (Sequence -> LLM Model)
1.  导航至 **Sequence** 标签页，然后选择 **LLM Model**。
2.  在右侧栏，使用 "Reload Model" 选择您想要的架构（如 Pytorch）和模型（如 Qwen）。
3.  调整参数，如 `temperature`（创造力）和 `max_tokens`（长度）。
4.  在聊天框中输入您的消息并按 **Send**。

#### B. 生成图像 (Image -> Text2Image Model)
1.  导航至 **Image** 标签页，然后选择 **Text2Image Model**。
2.  输入 **Positive Prompt**（正向提示词）描述您想看到的内容。
3.  （可选）输入 **Negative Prompt**（负向提示词）描述您想避免的内容。
4.  在右侧调整 `Width`（宽）、`Height`（高）和 `Inference Steps`（推理步数）。
5.  点击 **Generate**。生成的图像将显示在输出面板中。

#### C. 语音合成 (Audio -> TTS Model)
1.  导航至 **Audio** 标签页，然后选择 **TTS Model**。
2.  从右侧面板选择一个模型，如 `ChatTTS` 或 `CosyVoice`。
3.  输入您想要转换为语音的文本。
4.  点击 **Generate**。您可以试听或下载生成的音频文件。

### 4. 高级用法

-   **模型切换**：您可以在每个标签页的右侧配置面板中随时切换模型。系统会自动处理加载/卸载。
-   **历史记录**：LLM 标签页支持查看聊天历史和元数据。
-   **API 访问**：由于 UI 基于 Gradio 构建，您也可以通过 API 端点访问功能（查看 Gradio 页面底部的 "Use via API" 链接）。
-   **向量数据库配置**：
    -   数据存储在 `db/milvus/data/milvus.db`。
    -   配置文件：`config/storage_config.py`。
    -   您可以通过修改配置文件中的 `MILVUS_DATA_PATH` 来更改存储路径。

## 故障排除

-   **OOM (内存溢出)**：如果遇到内存错误，请确保没有其他重型应用程序在运行。系统在切换标签页时会自动释放内存，但运行非常大的模型（如 SDXL 或 70B LLM）仍需要足够的硬件支持。
-   **找不到模型 (Model Not Found)**：请检查模型权重文件是否已正确放置在 `config/*.py` 文件中指定的 `data/models/` 目录下。
-   **Milvus 连接错误**：确保已正确安装 `milvus-lite` 和 `pymilvus`。检查 `db/` 目录的写权限。
